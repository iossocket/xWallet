## ADDED Requirements

### Requirement: DatabaseStore as @Dependency
A `DatabaseStore` struct SHALL wrap `DatabaseQueue` and conform to `DependencyKey`. `liveValue` SHALL use `DatabaseService.dbQueue`. `testValue` SHALL provide an in-memory `DatabaseQueue` with migrations applied. Registered as `@Dependency(\.databaseStore)`.

#### Scenario: ChainRepository resolves DB via @Dependency
- **WHEN** `ChainRepository.liveValue` is constructed
- **THEN** it SHALL resolve `@Dependency(\.databaseStore)` inside closure bodies
- **AND** SHALL NOT reference `DatabaseService.dbQueue` directly

#### Scenario: WalletRepository resolves DB via @Dependency
- **WHEN** `WalletRepository` is used in `WalletClient.liveValue`
- **THEN** the `DatabaseQueue` SHALL be obtained via `@Dependency(\.databaseStore)`
- **AND** SHALL NOT reference `DatabaseService.dbQueue` directly

#### Scenario: In-memory DB for integration tests
- **WHEN** a test overrides `databaseStore` with an in-memory `DatabaseQueue`
- **THEN** Repository operations SHALL execute against the in-memory database
- **AND** no files SHALL be written to disk

### Requirement: KeychainStore as @Dependency
A `KeychainStore` `@DependencyClient` struct SHALL wrap Keychain operations and conform to `DependencyKey`. `liveValue` SHALL delegate to the existing `KeychainService` implementation with `kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly` + `.biometryCurrentSet`. `testValue` SHALL be auto-generated by the macro (unimplemented stubs). Registered as `@Dependency(\.keychainStore)`.

#### Scenario: WalletRepository resolves Keychain via @Dependency
- **WHEN** `WalletRepository` is used in `WalletClient.liveValue`
- **THEN** the Keychain access SHALL be obtained via `@Dependency(\.keychainStore)`
- **AND** SHALL NOT construct `KeychainService()` directly

#### Scenario: Keychain security policy preserved
- **WHEN** `KeychainStore.liveValue` is used
- **THEN** it SHALL use `kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly` with `SecAccessControl` flag `.biometryCurrentSet`
- **AND** SHALL NOT weaken the access control policy

#### Scenario: Tests use mock closures instead of protocol conformance
- **WHEN** tests need a mock Keychain
- **THEN** they SHALL construct `KeychainStore` with closure overrides (e.g. `KeychainStore(saveData: { _, _, _ in }, ...)`)
- **AND** SHALL NOT use `InMemorySecurityStore: SecurityStore` protocol conformance (protocol is removed)

### Requirement: HTTPService as @Dependency
An `HTTPService` `@DependencyClient` struct SHALL wrap HTTP operations and conform to `DependencyKey`. `liveValue` SHALL use the existing `URLSession`-based implementation. `testValue` SHALL be auto-generated by the macro (unimplemented stubs). Registered as `@Dependency(\.httpService)`.

#### Scenario: PriceRepository resolves HTTP via @Dependency
- **WHEN** `PriceRepository.liveValue` constructs price providers
- **THEN** the HTTP client SHALL be obtained via `@Dependency(\.httpService)`
- **AND** SHALL NOT reference `AppHTTPClient.live` or `HTTPClient.shared` directly

#### Scenario: TransactionHistoryClient resolves HTTP via @Dependency
- **WHEN** `TransactionHistoryClient.liveValue` makes network requests
- **THEN** the HTTP client SHALL be obtained via `@Dependency(\.httpService)`
- **AND** SHALL NOT reference `AppHTTPClient.live` directly

### Requirement: Repository renames
`ChainDataSource` SHALL be renamed to `ChainRepository`. `WalletDataSource` SHALL be renamed to `WalletRepository`. All callers SHALL be updated accordingly.

#### Scenario: ChainRegistryClient uses ChainRepository
- **WHEN** `ChainRegistryClient.liveValue` accesses chain data
- **THEN** it SHALL resolve `@Dependency(\.chainRepository)`
- **AND** the type SHALL be `ChainRepository` (not `ChainDataSource`)

#### Scenario: WalletClient uses WalletRepository
- **WHEN** `WalletClient.liveValue` accesses wallet data
- **THEN** it SHALL resolve `@Dependency(\.walletRepository)`
- **AND** the type SHALL be `WalletRepository` (not `WalletDataSource`)

### Requirement: No static singletons for infrastructure
After migration, `DatabaseService.dbQueue` (static let), `HTTPClient.shared` (static let), and `AppHTTPClient.live` (static var) SHALL NOT be referenced from any `liveValue` closure. All infrastructure access SHALL go through `@Dependency`.

#### Scenario: No direct singleton references in liveValue
- **WHEN** searching for `DatabaseService.dbQueue`, `HTTPClient.shared`, `AppHTTPClient.live`, `KeychainService()` in client/repository files
- **THEN** zero references SHALL be found in `liveValue` implementations
